# Config Discovery Agent

This directory defines the automation that keeps this repository aware of new official configuration guidance for the AI tools it covers.

## Goal

The agent looks for changes in vendor documentation, release feeds, and admin policy pages for:

- Claude Code
- Cursor
- GitHub Copilot
- Codex CLI and Codex Desktop
- Continue.dev
- Windsurf
- Tabnine
- Amazon Q Developer
- Gemini CLI and Google Gemini
- Claude Desktop
- OpenAI Platform
- Claude API

When a monitored source changes, the scheduled workflow opens a pull request with:

1. Updated source fingerprints in `config-discovery/source-state.json`
2. A review report in `config-discovery/reports/latest.md`
3. A checklist that points reviewers to `config-discovery/ROLLOUT_AGENT_PROMPT.md`

The scanner does not blindly rewrite tiered security configs. Official docs often include broad feature announcements, examples, or UI copy that should not become hardened policy without review. The pull request is the handoff point for a human reviewer or coding agent to decide whether a config, rationale document, deployment path, or rollout note needs to change.

## Files

| Path | Purpose |
|------|---------|
| `sources.json` | Official URLs monitored by the scanner. |
| `source-state.json` | Last known fingerprint and metadata for each source. Generated by the scanner. |
| `reports/latest.md` | Most recent change report. Generated only when changes are detected. |
| `reports/update-YYYYMMDD-HHMMSS.md` | Timestamped report for each detected change set. |
| `ROLLOUT_AGENT_PROMPT.md` | Prompt to give a coding agent when a discovery PR requires config updates. |
| `../scripts/discover_config_updates.py` | Standard-library Python scanner used locally and by GitHub Actions. |
| `../.github/workflows/config-discovery.yml` | Scheduled workflow that creates pull requests. |

## Operating model

1. The workflow runs on a schedule and on manual dispatch.
2. The scanner downloads each source in `sources.json`.
3. HTML, JSON, and text responses are normalized to reduce noise from scripts, assets, and volatile API fields.
4. The normalized content is hashed.
5. If a hash differs from `source-state.json`, the source is listed in a report and the state file is updated.
6. The workflow uses `peter-evans/create-pull-request` to open or update a PR on branch `automation/config-discovery-updates`.

## Required GitHub settings

In the repository that uses this automation:

1. Enable GitHub Actions.
2. Set workflow permissions to **Read and write permissions**.
3. Allow GitHub Actions to create and approve pull requests if your organization requires that setting.
4. Keep branch protection on `main`, and require a human reviewer before merging discovery PRs.

No external secrets are required for the default scanner. It uses public documentation sources and `GITHUB_TOKEN` for pull request creation.

## Reviewing a discovery PR

Use this triage order:

1. Read `config-discovery/reports/latest.md`.
2. Open each changed official source listed in the report.
3. Decide whether the change affects a security control, deployment path, validation command, or admin policy.
4. If config updates are needed, run a coding agent with `config-discovery/ROLLOUT_AGENT_PROMPT.md` and include the changed source links as context.
5. Keep any edits scoped to the affected tools and tiers.
6. Validate changed JSON, YAML, TOML, and shell examples before merging.

## Adding or changing sources

Edit `sources.json` and add one object per official source:

```json
{
  "id": "tool-topic",
  "tool": "Tool Name",
  "category": "admin-policy",
  "url": "https://official.vendor.example/docs/policy",
  "notes": "Watch for policy settings that affect tiered files."
}
```

Guidelines:

- Prefer official vendor documentation, official release feeds, or official raw docs in vendor repositories.
- Prefer stable Markdown or API URLs over heavily client-rendered pages.
- Use `?per_page=10` for GitHub release APIs to keep fingerprints small and stable.
- Do not add community blogs, forum posts, or social media feeds as enforcement sources.

Run locally after editing:

```bash
python3 -m json.tool config-discovery/sources.json >/dev/null
python3 scripts/discover_config_updates.py --dry-run
```

## Local commands

Bootstrap or refresh the state file:

```bash
python3 scripts/discover_config_updates.py
```

Check sources without writing files:

```bash
python3 scripts/discover_config_updates.py --dry-run
```

Write a report even when no source changed:

```bash
python3 scripts/discover_config_updates.py --write-no-change-report
```

## False positives and noisy sources

The scanner removes common volatile fields from JSON feeds, such as asset download counts, uploader objects, reactions, and API node IDs. It also strips HTML scripts and styles before hashing documentation pages.

If a source still changes too often without security relevance:

1. Prefer a raw Markdown URL from the same vendor docs site.
2. Narrow the source to a specific page instead of a docs landing page.
3. Remove the source if it cannot produce useful review signals.

## Security boundaries

- The scanner never executes downloaded content.
- The scanner never reads secrets or local tool credentials.
- The scanner does not call paid model APIs.
- Generated PRs require normal branch protection and human review.
- Config updates should still follow the rollout-engineering requirements in `ROLLOUT_AGENT_PROMPT.md`.
